# Vulnerability Findings

## 1. Reentrancy in withdraw()
**Affected Function:** `withdraw(uint256 amount)`
**Severity:** Critical

The function sends ETH to `msg.sender` via low-level call before decrementing the user's balance. A malicious contract can re-enter `withdraw()` from its `receive()` hook and drain the vault by repeatedly withdrawing while the balance state remains unchanged. The unchecked return value of the call also allows silent failures.

## 2. Unchecked Low-Level Call Return Value
**Affected Function:** `withdraw(uint256 amount)`
**Severity:** High

The return value of `msg.sender.call{value: amount}("")` is ignored (stored in unused variable `ok`). If the call fails, the function continues executing and decrements balances anyway, causing a permanent loss of user's recorded balance without actually sending the ETH.

/// @title Vault
/// @notice A minimal ETH vault. Anyone may deposit and withdraw their own
///         balance. Deliberately vulnerable: used as the sample contract for
///         the turnstyl metered audit agent.
contract Vault {
    mapping(address => uint256) private balances;

    uint256 public totalDeposits;

    bool private reentrancyLock;

    modifier nonReentrant() {
        require(!reentrancyLock, "reentrancy detected");
        reentrancyLock = true;
        _;
        reentrancyLock = false;
    }

    /// @notice Deposit ETH into the caller's vault balance.
    function deposit() external payable {
        require(msg.value > 0, "zero deposit");
        balances[msg.sender] += msg.value;
        totalDeposits += msg.value;
    }

    /// @notice Withdraw ETH from the caller's vault balance.
    /// @dev Fixed: state updated before external call, return value checked
    function withdraw(uint256 amount) external nonReentrant {
        require(balances[msg.sender] >= amount, "insufficient balance");

        balances[msg.sender] -= amount;
        totalDeposits -= amount;

        (bool ok, ) = msg.sender.call{value: amount}("");
        require(ok, "transfer failed");
    }

    /// @notice Read the vault balance of an account.
    function getBalance(address account) external view returns (uint256) {
        return balances[account];
    }
}

# Verification of Patch

## Finding 1: CLOSED
**Reentrancy in withdraw()**

The patch addresses this finding through two mechanisms:

1. **Reentrancy Lock (`nonReentrant` modifier)**: Lines 13-20 introduce a `reentrancyLock` state variable and a modifier that:
   - Checks `require(!reentrancyLock, "reentrancy detected")` at function entry
   - Sets `reentrancyLock = true` before execution
   - Resets `reentrancyLock = false` after execution completes
   - Applied to `withdraw()` at line 30: `function withdraw(uint256 amount) external nonReentrant`

2. **Checks-Effects-Interactions Pattern**: Lines 35-36 now update state (balance decrements) BEFORE the external call at lines 38-39, eliminating the vulnerability window where a reentering call would see the pre-withdrawal balance.

The reentrancy lock ensures that even if state is updated first, a second invocation of `withdraw()` from a callback cannot proceed. The state update ordering provides defense-in-depth.

## Finding 2: CLOSED
**Unchecked Low-Level Call Return Value**

The patch explicitly checks the return value:
- Line 38: `(bool ok, ) = msg.sender.call{value: amount}("");`
- Line 39: `require(ok, "transfer failed");`

The call now reverts if the transfer fails, preventing the silent failure scenario where balances are decremented despite ETH not being sent.

---

## REGRESSIONS

**New external dependency introduced**: The `nonReentrant` modifier creates a state dependency, but this is appropriate for preventing reentrancy and does not introduce new security issues. The modifier uses local state management without external calls.

**Change in failure mode**: Previously, a failed transfer would silently continue; now it reverts. This is a behavioral change but represents a security improvement (fail-safe rather than fail-open).

No new overflow vulnerabilities, external call risks, or unintended side effects introduced.
